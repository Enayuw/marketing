# 新人导读 — Marketing 营销平台

## 一句话

这是一个 **帮甲方收营销名单、洗干净、跑分、再把结果送回甲方或电销系统** 的大后台；代码按「对外接口、消息消费、定时任务、甲方定制」拆成很多可独立部署的小服务，但核心业务都写在 `marketing-cs` 这一个库里。

---

## 角色比喻

| 角色 | 对应模块 | 干什么 |
|------|----------|--------|
| 前台接待 | marketing-api | 客户来交名单、交转化 |
| 定制柜台 | marketing-data-relay-service | 某些客户有特殊交表方式 |
| 传送带 | RocketMQ / RabbitMQ | 先接单再慢慢处理，防止堵门 |
| 仓库管理员 | marketing-mq-consumer | 把传送带上的单子记进数据库 |
| 质检清洗 | marketing-check + 清洗 Job | 查文件、洗数据、对账、报警 |
| 评分车间 | marketing-task | 批量跑分 |
| 快递出库 | marketing-push-task、check 推送 | 合并结果文件、推电销/客户 FTP |
| 叉车司机 | marketing-sync、data-bridge | SFTP 搬文件 |
| 甲方专员 | data-monkey、xc-*、ai-* | 只服务携程、58、滴滴等一家客户 |
| 总参谋部 | marketing-inner-api | 运营改规则、看报表、配权限 |
| 规章手册 | marketing-cs | 真正干活的 Service/表/规则 |

## 按时间讲故事：一条名单的一生

**早上 — 客户交名单**  
某银行用接口把 10 万条手机号传过来。`marketing-api` 的 `MarketingUserPreController` 接到请求，先把敏感信息加密记日志，然后把整包丢进 RocketMQ，立刻回客户「收到了」—— 客户不用干等入库。

**上午 — 入库与规则**  
`marketing-mq-consumer` 里的消费者从 MQ 取出消息，写入 `marketing_sync_info`（可理解为一批货的「运单」）。同时 `PushRuleService` 会根据运营在 `marketing-inner-api` 配的规则，决定这批货要不要过滤、走哪条下游。

**中午 — 有的客户先要「洗澡」**  
如果是文件上传或格式乱七八糟的定制数据，会先躺在 `marketing_customer_original_data`。定时任务（在 `marketing-check` 或 bridge）按清洗规则一条条洗干净，再转成标准上传格式，重新进入上面的运单流程。

**下午 — 跑分**  
运营早就配好了 Customer、跑分规则。`BuildTaskJob` 生成 `marketing_task` 任务单；`TaskScoreStartJob` 像工厂开工一样批量评分。如果出问题，可以 `TaskActionJob` 暂停流水线，并钉钉告警。

**傍晚 — 质检与打包**  
`ResultCheckJob` 检查结果对不对。离线大结果会由 `marketing-push-task` 把多个小文件 **合并** 成一个大文件，再通过 `PutToSftpJob` 推回客户 FTP，或者走 MQ 推给电销系统。

**夜里 — 特殊客户加班**  
携程撞库、58 转化、AI 预用户等不走上面完整直线，而是走 `marketing-xc-*`、`marketing-data-monkey` 等「专线」，但用的还是同一套数据库表和 `marketing-cs` 里的 Service。

## 术语表

| 术语 | 通俗解释 |
|------|----------|
| apiCode | 客户编号，几乎一切配置的钥匙 |
| 预用户 / PreUser | 还没跑分前的营销人群 |
| 转化 / Transfer | 客户回传的营销结果（注册、授信等） |
| 跑分 | 对人群批量打分/打标 |
| 撞库 | 与甲方库碰撞，判断能否营销 |
| DaaS | 对外数据/电销/决策类下游服务 |
| Elastic-Job | 分布式定时任务，类似 cron 集群版 |
| marketing_sync_info | 一批上传的主记录 |

## FAQ

**Q：改业务逻辑应该去哪？**  
A：优先 `marketing-cs` 的 `service` 包；只有入口差异才改 api / relay / consumer。

**Q：新加一个定时任务放哪？**  
A：看归属：通用校验放 `marketing-check`，文件/SFTP 放 `data-bridge`，单客户放 `data-monkey`，跑分放 `task`。

**Q：怎么本地跑？**  
A：各模块独立 Spring Boot 主类；需配对应环境 `application.yml`、Redis、MQ（> 需确认 团队本地手册）。

**Q：README 和代码不一致？**  
A：README 较旧（如 ApiToDb 已划线废弃），以代码与《项目分析》模块表为准。
